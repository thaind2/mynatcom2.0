Selfcare Batch 1 / 2 · Daily Essentials

5 tính năng — Multi-account, Cước & lịch sử, Mua gói data, Mua gói thoại/SMS, Notification Center — chiếm ≥85% lượt mở app của Persona Marie/Jean/Stephania. Đây là nền tảng kỹ thuật bắt buộc trước khi mọi Engagement feature có thể hoạt động.

#1 — Quản lý đa thuê bao (Multi-account · Chuyển nhanh giữa các số Natcom)

Must Effort M KPI: Activation per number · DAU Phase: G1 — sprint 3–4

1. Định nghĩa

Một tài khoản My Natcom 2.0 quản lý tối đa 5 số Natcom (mobile + FTTH) cùng lúc. Switch context giữa các số trong <2s mà không cần đăng xuất/đăng nhập. Mỗi số có usage, gói, notification, ngôn ngữ, biometric riêng biệt. Đáp ứng văn hóa "thiết bị chia sẻ trong gia đình Haiti" (Nguyên tắc 5) và mô hình B2B của Patrick (P6 — quản lý số nhân viên).

2. Persona phục vụ

Patrick (P6 — multi-employee chính), Marie (P1 — số cá nhân + shop), Pierre (P4 — share máy với con cái), Wisline (P5 — quản lý số người thân tại Haiti từ Mỹ qua remote). Stephania (P3), Jean (P2) chỉ dùng 1-2 số.

3. User flow chính

  1. Profile → "Thuê bao mwen yo" → list số đã link với role (Primary/Sub).
  2. Thêm số: nhập số HT → OTP verify gửi tới số đó → confirm. Số mới link với account.
  3. Header top có switcher chip hiển thị số hiện tại; tap → dropdown chọn số khác → context refresh <2s.
  4. Mỗi số có settings riêng: notification on/off, ngôn ngữ Creole/Pháp/Anh, biometric, auto-pay.
  5. Admin role (Patrick) có quyền xem usage tổng + per-employee, set limit per số, lock SIM remote nếu nhân viên nghỉ.
  6. USSD fallback: *155*N# để switch số mặc định (N=1-5).

4. Wireframe

Xem S1 — màn "Thuê bao mwen yo" với 4 active numbers + 1 add slot, switcher chip top, mỗi card hiển thị plan + balance + last activity.

5. Edge case

  • Số đã link với account khác → reject + hint "Sa-a deja konekte ak yon kont. Kontakte CSKH."
  • Mất quyền số (chuyển SIM cho người khác) → owner cũ bị auto-remove sau 30 ngày inactive trên số đó.
  • Max 5 số/account cứng. Patrick có nhu cầu >5 → upgrade B2B tier "Antrepriz" (Đợt 2).
  • Biometric: user chọn shared (1 lần unlock cả 5 số) hoặc per-number (mỗi số PIN/biometric riêng — bảo mật cao).
  • Switch context giữa chừng giao dịch Natcash đang chạy → confirm hủy giao dịch trước.
  • Wisline (diaspora) link số Haiti từ US/CA → cần KYC Tier 1 + verify ownership qua SMS đến số HT đó (chống fraud).

6. Phụ thuộc

  • Telecom backend (link multi-MSISDN cho 1 user_id).
  • OTP gateway.
  • KYC light per number.
  • Multi-context UI state machine.
  • USSD gateway (*155*N#).
  • mBccs Haiti (Viettel back-office) — cho admin role B2B.

7. Acceptance criteria

  • AC1: Switch context giữa số <2s.
  • AC2: Add số + OTP verify hoàn tất <30s.
  • AC3: Settings per number isolated 100% (không leak).
  • AC4: Max 5 số/account enforce cứng.
  • AC5: USSD switch *155*N# hoạt động cho user feature phone.
  • AC6: Admin B2B view usage tổng + per-employee có audit log.

8. KPI riêng

  • % user multi-number: ≥ 18% MAU.
  • Avg số/user multi-account: ≥ 2.4.
  • Activation lift per sub-number: ≥ +25% (số phụ được "ăn theo" số chính).
  • FTTH + Mobile link rate: ≥ 35% trên FTTH user (cross-sell signal).
  • Admin B2B adoption: ≥ 60% Patrick-persona user.

9. Priority

Must — Nguyên tắc 5 cốt lõi. Không có multi-account thì Pakèt Familial (#17 Engagement) và Patrick persona đều thất bại.

10. Phase

Đợt 1 — Giai đoạn 1 (Foundation), sprint 3–4. Là infrastructure bắt buộc trước các feature khác.

Nguyên tắc thiết kế áp dụng (6/10) 1 · Creole mặc định 5 · Multi-profile (core) 6 · USSD fallback *155*N# 7 · Bảo mật cấp banking (KYC per number) 8 · Accessibility 10 · Observable (audit admin role)

Wireframe S1 — Thuê bao mwen yo (Multi-account dashboard)

S1 — Multi-account: số primary chip top · 3 sub-numbers (Jean mobile · Marie FTTH · Sophia child allowance) + 1 add slot · USSD fallback hint · admin B2B preview cho Patrick.

#2 — Tra cứu cước & lịch sử giao dịch (Konsilte fakti ak istwa)

Must Effort S KPI: DAU · CSKH call -30% Phase: G1 — sprint 3–4

1. Định nghĩa

Dashboard cước trực quan: 3 chỉ số (hôm nay, tuần, tháng) trên home + chi tiết sao kê theo dịch vụ (voice/data/SMS/VAS/roaming). Xuất file PDF/CSV qua email cho user/kế toán (Patrick persona). Hiển thị đa ngôn ngữ Creole/Pháp/Anh. Đây là feature gốc rễ giảm CSKH call về cước — chi phí hỗ trợ lớn nhất của Natcom hiện tại.

2. Persona phục vụ

Marie (P1 — quản lý dòng tiền hằng ngày), Patrick (P6 — báo cáo doanh nghiệp hàng tháng), Jean (P2 — kiểm tra nhanh balance), Stephania (P3 — track gói data đã dùng), Pierre (P4 — qua USSD nếu literacy thấp).

3. User flow chính

  1. Home tab → card "Fakti mwen" ở top hiển thị 3 KPI: jodi a, semèn sa, mwa sa (HTG).
  2. Tap → dashboard chi tiết: pie chart usage theo dịch vụ + list giao dịch 30 ngày.
  3. Filter: theo dịch vụ (voice/data/SMS/VAS), theo khoảng thời gian, theo số (nếu multi-account).
  4. Tap giao dịch → detail: thời gian, dịch vụ, destination (nếu voice), gói áp dụng.
  5. Export: PDF (Creole/Pháp/Anh) hoặc CSV → gửi email user (mặc định) hoặc kế toán (Patrick set up).
  6. Push tự động: "Gòl data ou rete 200 MB · 20% kite" khi gói còn 20% / 10% / 5%.
  7. USSD fallback: *155*1# show balance, *155*2# show usage tháng.

4. Wireframe

Xem S2 — Fakti dashboard với 3 KPI top, pie chart usage 6 services, transaction list 30 ngày + filter, export CTA.

5. Edge case

  • Lịch sử quá dài (Patrick 12 tháng) → pagination + filter, không render full list (perf).
  • Offline → show cached snapshot last sync + label "Dènye mizajou: 2h ago".
  • Cước chưa update realtime (billing delay) → label "Fakti pa fini mete-a-jou" + estimated.
  • Export file lớn >5 MB → email link download thay vì attachment trực tiếp (mobile data save).
  • Export PDF tiếng Creole → font Unicode support đầy đủ (test Pháp accents + Creole quirks).
  • Roaming charges chậm 24-72h (settlement với partner) → label rõ "Roaming charges may take up to 72h".

6. Phụ thuộc

  • Billing backend (real-time + aggregator).
  • BI/usage data warehouse.
  • File export service (PDF/CSV generator).
  • Email gateway.
  • USSD gateway.
  • Notification preference engine.

7. Acceptance criteria

  • AC1: Dashboard load <2s với 30 ngày data.
  • AC2: Filter realtime <500ms.
  • AC3: Export PDF/CSV gửi email <30s.
  • AC4: Offline cache giữ 7 ngày, label rõ ràng "Pa konekte".
  • AC5: Push usage warning đúng 3 mức 20%/10%/5%.
  • AC6: USSD *155*1# / *155*2# hoạt động 24/7 (legacy core path).

8. KPI riêng

  • DAU lift (mở dashboard ≥1 lần/ngày): ≥ +20 points trên baseline.
  • CSKH call về cước: giảm ≥ 30% trong 90 ngày sau launch.
  • Export usage rate: ≥ 12% MAU (sign of trust).
  • % Patrick persona export hằng tháng: ≥ 65%.
  • Push CTR usage warning: ≥ 35% (drive top-up).

9. Priority

Must · Effort thấp, ROI cao nhất batch (giảm CSKH cost). Là feature gốc rễ niềm tin user vào Natcom.

10. Phase

Đợt 1 — Giai đoạn 1 (Foundation), sprint 3–4. Launch sớm cùng Multi-account.

Nguyên tắc thiết kế áp dụng (6/10) 1 · Creole mặc định 2 · Offline-capable (cache 7 ngày) 6 · USSD fallback *155*1#/*2# 8 · Accessibility (font adjustable, WCAG) 9 · Push có giới hạn (chỉ 3 mức) 10 · Observable

Wireframe S2 — Fakti mwen Dashboard

S2 — Fakti mwen: 3 KPI cards (today/week/month) · pie chart 5 services · filter chips · 30-day transaction list · usage warning 20% · export PDF/CSV CTA.

#3 — Mua/đổi gói data (Achte gòl Done · catalog + AI gợi ý)

Must Effort M KPI: ARPU data · Conversion Phase: G1–G2 — sprint 4–6

1. Định nghĩa

Catalog tất cả gói data (daily/weekly/monthly/topup), filter theo nhu cầu (giá rẻ / tốc độ / total GB), mua nhanh thanh toán qua Natcash hoặc top-up code. AI gợi ý gói cá nhân hóa dựa trên usage pattern user. Lịch sử gói cũ + spending chart. Tích hợp Auto-pay (#16 Engagement) để giảm 5-10% giá.

2. Persona phục vụ

Stephania (P3 — heavy data, TikTok/IG), Jean (P2 — cần data rẻ), Marie (P1 — daily check), Patrick (P6 — gói B2B). Pierre (P4) qua đại lý hoặc USSD.

3. User flow chính

  1. Home tab → card "Gòl Done" hiển thị status gói hiện tại + AI gợi ý "Pou ou" (Recommended for you).
  2. Tap → catalog full screen với 3 tab: Pou ou (AI), Pi popilè, Tout.
  3. Filter chips: Price <50 / <100 / <200 HTG · Speed 4G/5G · Duration daily/weekly/monthly.
  4. Tap gói → detail: data total, validity, speed cap, terms.
  5. Confirm → Natcash debit với PIN/biometric → gói activate <30s + push xác nhận.
  6. Auto-pay toggle inline: "🔁 Renive otomatik? Jwenn 5% rabè + X2 Points"
  7. Lịch sử gói + spending pattern chart 12 tháng.
  8. USSD fallback: *155*3# để mua quick gói last-bought.

4. Wireframe

Xem S3 — Catalog với AI recommendation badge "Pou ou" trên 2 gói, filter chips, 4 gói trong list (current/recommended/popular/discount), Auto-pay CTA.

5. Edge case

  • Active gói còn hiệu lực → mua mới sẽ stack (cộng dồn) hoặc replace (user chọn) → confirm rõ.
  • Natcash balance thiếu → suggest nạp + payment alternative: top-up code, agent, card Visa.
  • Gói promotional → countdown expiry "Pri sa-a ap fini nan 2j".
  • AI gợi ý fail (engine down) → fallback top-3 best sellers + label "Pi popilè".
  • Roaming user → catalog hiển thị thêm gói roaming inline.
  • Patrick B2B → catalog có tab "Antrepriz" với volume discount.

6. Phụ thuộc

  • Catalog service (CMS-driven).
  • Natcash core (debit + auto-pay).
  • AI recommendation engine (chung #14 Misyon Jou AI).
  • Auto-pay engine (chung #16 Engagement).
  • Push notification + activation confirmation.
  • USSD gateway (*155*3#).

7. Acceptance criteria

  • AC1: Activate gói <30s sau Natcash debit success.
  • AC2: Catalog filter realtime <300ms.
  • AC3: AI fallback <2s khi engine fail.
  • AC4: Lịch sử 12 tháng accessible <3s.
  • AC5: Auto-pay toggle apply discount 5%/10% đúng.
  • AC6: USSD *155*3# quick buy hoạt động.

8. KPI riêng

  • ARPU data lift: ≥ +18% so với app cũ.
  • Conversion catalog → purchase: ≥ 25%.
  • AI recommendation CTR: ≥ 38% (vs ~22% no-AI baseline).
  • Auto-pay attach rate: ≥ 30% gói mới.
  • Avg purchase value: ≥ +15% (AI nudge sang gói cao hơn).

9. Priority

Must — ARPU driver chính. Đây là feature mà 60-70% revenue Natcom Đợt 1 phụ thuộc vào.

#10 — Notification Center (Sant notifikasyon)

Must Effort S KPI: DAU · CTR notif CTA Phase: G1 — sprint 3–4

1. Định nghĩa

Hộp thư app categorized: Fakti (cước, gói sắp hết), Pwomosyon (ưu đãi cá nhân hóa), Sèvis (FTTH maintenance, network update), Sekirite (alerts đăng nhập, KYC). User có quyền tắt từng nhóm trừ Sekirite (compliance). Đồng bộ với SMS legacy. Áp dụng Nguyên tắc 9 push limited.

2. Persona phục vụ

Mọi user. Marie (P1 — alerts giao dịch quan trọng), Patrick (P6 — FTTH SLA alerts), Stephania (P3 — promo gói data trẻ).

3. User flow chính

  1. Top bar có icon 🔔 + badge số chưa đọc.
  2. Tap → list categorized với 4 tab (Tout · Fakti · Pwomosyon · Sèvis).
  3. Mỗi notification có CTA inline (vd "Renive gòl la" → flow #3).
  4. Settings → toggle per category (Sekirite force-on, không tắt được).
  5. Long-press notification → archive / mark read / mute source.
  6. Push system override (vd Critical: payment fail, KYC requested) → vẫn hiển thị ngay cả khi user tắt category.

4. Wireframe

Không có wireframe riêng cho B1 Selfcare — pattern category list quen thuộc, sẽ rảnh sẽ vẽ trong B2 hoặc khi Natcom yêu cầu.

5. Edge case

  • Notification quá nhiều (Patrick 100+/tháng) → pagination + filter.
  • Critical alerts không cho tắt: payment fail, KYC required, security login.
  • Offline → queue local, sync khi online (TTL 7 ngày).
  • Multi-account: notification context theo số active hiện tại, có option "Tout nimèwo" để xem tất cả.
  • SMS legacy sync: SMS quan trọng của Natcom (vd OTP) cũng ghi vào Notification Center, có badge "Soti nan SMS".

6. Phụ thuộc

  • Push gateway (FCM).
  • In-app messaging service.
  • Notification preference engine (kết nối mọi feature).
  • Aggregator (tổng hợp event từ billing/security/promo).
  • SMS legacy sync bridge.

7. Acceptance criteria

  • AC1: Load <2s với 50 notifications recent.
  • AC2: Mark read realtime <500ms.
  • AC3: Critical alerts force-show ngay cả khi category off.
  • AC4: Settings toggle apply <30s.
  • AC5: SMS legacy sync vào center trong <5 phút.
  • AC6: Quota 3 push/ngày/user enforce (Nguyên tắc 9), trừ Critical.

8. KPI riêng

  • % user mở notification daily: ≥ 40% MAU.
  • CTR notification CTA: ≥ 15%.
  • % Critical alerts dismissed within 1h: ≥ 90% (security/payment).
  • % user customize preference (tắt category): ≥ 25% (tôn trọng user choice).

9. Priority

Must · Hub cho mọi push từ các feature khác. Không có Notification Center thì push của các Engagement/Selfcare features sẽ rời rạc, hỗn loạn.
